Troubleshooting

Use these checks when activation, project detection, dependency generation, or existing-file protection does not behave as expected.

kite: command not found

echo 'export PATH="$PATH:$HOME/.pub-cache/bin"' >> ~/.zshrc
source ~/.zshrc
which kite
kite --version

Alternative:

dart pub global run kite:kite --version

Downloading packages and rebuilding every run

This commonly appears while Kite is activated from a local path and its package source has changed. Re-run local activation after validating the package:

cd /path/to/kite
dart pub get
dart analyze
dart test

dart pub global deactivate kite
dart pub global activate --source path .

Existing shared file prompt during feature generation

A feature template may require Riverpod or another shared foundation. If those files already exist and must be preserved:

kite --feat:clean settings --skip-existing

Do not select overwrite-all or use --force unless you intentionally want to replace the existing foundation.

Generation cancelled by the user

This message means Kite encountered an existing-file conflict and the interactive response quit the complete generation plan. No partial write should be treated as successful. Preview and choose a conflict strategy:

kite --feat:clean settings --dry-run
kite --feat:clean settings --skip-existing

Not a Flutter project

Run the command inside a project containing pubspec.yaml, or provide a path:

kite doctor --path /path/to/flutter_app
kite init --path /path/to/flutter_app

JSON part file is missing

After adding actual fields to a generated JSON model or DTO:

flutter pub get
dart run build_runner build --delete-conflicting-outputs

Generated imports fail

dart format .
flutter pub get
flutter analyze

When developing Kite itself, also run:

python3 tool/validate_templates.py

Reset local activation

dart pub global deactivate kite
dart pub cache repair
dart pub global activate --source path /absolute/path/to/kite
